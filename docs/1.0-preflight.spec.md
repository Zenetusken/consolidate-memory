## The go/no-go gate

GO = the user's explicit call. At go:
1. Author the `## [1.0.0]` CHANGELOG section (the single source of truth).
2. `./release.sh --expect major` (dry-run) → review → `--stage` (bump + release PR)
   → merge the PR → `./release.sh --expect major --finalize` (tag the merge commit +
   GH Release). Pre-bump preferred: with plugin.json already at 1.0.0 on the merged
   feature line, `--stage` is a no-op and `--finalize` alone releases.
3. The auto-update cycle ships 1.0.0 to every installed copy at next CC startup.

NO-GO (any item) keeps the current 0.4.x engineering line and re-runs the
pre-flight when the item clears.
